# Progress-driven climbing and excavation

Implemented after aerial presentation `190116aa`, preserving Claude's `191ac720` neighbour-region findings. This is a C8 presentation slice. Excavation has native gameplay evidence; climbing is implemented and geometrically/staged-natively verified, with live canopy acceptance still unproven.

## Runtime

`work-motion.js` reads actual `climb.height`, `burrowWork.elapsed` and perched state. Its bounded observer interpolates between received values over 80 ms, never extrapolates, freezes on the existing pause-aware display clock, and resets for world/anatomy/job changes, backwards time, observation gaps and cancelled work. Climb projection reads the canonical `CLIMBING.height` contract; no competing height authority is introduced.

`work-limbs.js` supplies alternating reaching/gripping phases locked to displayed climb height. A gripping foot gains exactly the local vertical offset lost by the torso's height projection, keeping its canopy point fixed during ascent or descent. Actual mounted gripping organs are staggered even on asymmetric, one-sided layouts so they cannot all release together. Perched bodies hold static grips. Real mounted digging forelimbs perform reach, pull and recovery strokes from actual excavation progress; the other limbs brace. Old walking/digging clocks cannot keep the brace feet moving when work progress is held.

`genvo.js`, `behavior.js` and `renderer.js` integrate these poses, use the same displayed height for torso and grips, and remove inappropriate walking bob from work. Active work bypasses stale sprite caches; paused and static perched poses retain keyed cache reuse. No tree, soil, passage, work cost, physical movement, eligibility, biological controller, original artwork or save schema was changed. Native32 and optional64/128 share the implementation.
