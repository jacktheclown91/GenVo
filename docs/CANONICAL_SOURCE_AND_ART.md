# Canonical source, art, and maintenance guide

## One current implementation

The playable entry point is `index.html` -> `src/main.js`. The authoritative runtime simulation is `src/sim/simulation.js`; persistence belongs to `src/persistence/save-manager.js` and world state to `src/world/world.js`. The detailed machine-readable authority map is `design/governance/implementation-authorities.json`. A second controller must never silently replace one of these.

For anatomical art there are **three deliberately distinct layers**, not three interchangeable sprite versions:

1. `src/lineage/part-registry.js`: authoritative names, sockets, and biological metadata of **73 parts**. Biological capacities are handled by `src/lineage/part-abilities.js`; drawing cannot grant an ability.
2. `src/render/part-sprites.js`: the current **single procedural runtime part-art catalog**; used by `src/render/genvo-draw.js` through `src/render/creature-assembler.js`. The actual game and the creature editor both use these drawing functions. 73/73 registry parts have an implemented drawing. The 32×32 authoring/art direction does *not* mean all live parts are already independently approved native 32×32 authored sheets.
3. `tools/creature-lab/` and `src/render/indexed-part-{art,renderer}.js`, `src/render/authored-draft-compiler.js`: separate **authoring/preview** paths. They are not selected by default in the gameplay import graph. Authored drafts must be reviewed and explicitly published to the runtime catalog. Do not count unfinished or uninstalled art as a playable upgrade.

`references/generated-sprite-sheets/` contains derived reference PNGs generated by `tools/export_sprite_sheets.cjs` from runtime drawing modules. They are *not* loaded by gameplay and must not become an independent pixel authority. The original standalone art-bible handoff is preserved intact as `references/archived-source-packages/GenVo8_Modular_Creature_Art_Bible_v1_Source_Documents.zip`; active copies of its identical design tables and documents live only in `docs/art/`, `design/art/` and `references/`. `Original (human) arts/` contains the creator's source artwork and must never be silently replaced or deleted. The tool-only phenotype adapter `src/lineage/phenotype-resolver.js` remains intentionally present because legacy contract tests depend on its compatibility behavior; removing it requires an explicit contract migration, not a filename-only guess.

## New mate-choice authority

`src/reproduction/mate-preferences.js` is the sole runtime genotype/trait preference evaluator. It derives physical cues from `src/organisms/species.js`, the existing animal genes and `src/lineage/part-abilities.js`; it does not provide a second genetics tree, reproduction controller or renderer. `src/sim/simulation.js` owns the actual birth and mating gates, `src/reproduction/reproduction.js` owns player mate-selection workflow, and `src/ecology/gestation.js` stores conception-time parent records. `src/reproduction/courtship-performance.js` owns the single finite display/arrival and local rival-comparison mechanism; `src/sim/simulation.js` calls it and remains authoritative for physical mating and pregnancy. `src/render/renderer.js` renders only its already-paid presentation state using existing creature poses. No second mating gate or sprite catalog exists.

## Cleanup rules

- **Never delete by filename alone.** Verify game-entry reachability; search test/tool imports and asset URLs; check save migrations, player settings, authorship, and original source art before moving anything. Runtime-unused is not synonymous with obsolete.
- The canonical audit (`node tools/canonical-source-audit.mjs
node tests/public-export.mjs`) compares the source import graph, checks known tool-only modules, 73-part catalog alignment, exact duplicate source bytes, generated export isolation, and UTF-8 validity. It is conservative: it cannot prove every exported function is exercised at runtime or that semantically duplicate behavior does not exist. New authorities require explicit map updates and separate runtime verification.
- Move genuine derived outputs under `references/` (or documented build output) rather than `assets/` that the game loads. Update their generation tool when moving them.
- Keep historical `reports/` evidence intact. It is excluded from the game and provenance source hash. Archive or compact it only with traceable paths and hashes, and never by substituting an old build into production. Avoid pass-numbered source copies and abandoned alternate entry points.
- Use one canonical source ZIP and one public-browser ZIP. Art tests, experimental probes, and provenance belong inside the canonical source; the public ZIP contains only what a browser needs.
- A cleanup is not complete without focused tests, source/public dependency parity, and a real browser smoke test when available; note failures and blockers without claiming success.

Export a browser-only directory with `node tools/export-public.mjs /path/to/empty/outside-directory`. This uses the **same** static source-module graph as the audit, ships only runtime-reachable ES modules and runtime assets, and excludes creature-art laboratory compilers and derived reference sprite sheets. Archive the resulting directory as the separate public ZIP.

Long-running historical natural-world tests are research/experiment receipts unless a controlled scenario explicitly requires their end-state. The ordinary regression suite should prefer invariants and purposeful gameplay checks.
