# Pass A0: topology and save compatibility preflight

Review-only clarification, October 17. No production code changed. Evidence: `save-compatibility-preflight.json`, generated by constructing and snapshotting current worlds without advancing ecological time.

## Confirmed behavior

| Case | Current result |
| --- | --- |
| Unchanged new-world mask with its environment | Restores; 3,271 water cells in the inspected seed. This checks restoration, not prolonged continuation. |
| Existing test adds river column and calls buildLandRegions/buildHydrology | Rejects with Environment water topology mismatch. All 122 added cells still have zero depth. |
| Environment record present, saved surface mask absent | Rejects with the same mismatch: fallback reconstructs the pre-coast generator while the environment record describes newer coastal geography. |
| Saved mask present, environment absent | Restores with legacy hydrology; 3,393 water cells after the test's declared topology edit. |

The two failures have distinct causes: an incoherent runtime edit transaction and an unversioned generator fallback. Fixing only depth on edited cells would leave the fallback failure unresolved. Weakening the topology validator would conceal both.

## Proposed repair sequence after review

1. Record generator/rule identity explicitly in new world snapshots; define exact inference for already-created snapshots using optional terrain/environment fields. Unknown or contradictory versions fail visibly.
2. Keep old masks authoritative when supplied. Without a mask, reconstruct the matching generator, not whichever generator is currently the default. Truly old records without environment retain the old freshwater generator; newer environment records retain their coastal generator.
3. Put physical topology changes at the World boundary. Existing explicit mask-edit/rebuild callers need a compatibility path that synchronizes fields and derived access without creating food or genetic state. New callers use a transaction with old/new physical state and a declared source/destination for water, salt and displaced material.
4. A runtime compatibility edit and corrupt serialized input are different: the former can use a documented transition; restore must not silently invent depth, freshwater, nutrients or a salt sink to make malformed data pass.
5. Rebuild accessibility, regions and render revisions once after a consistent transition. No double initialization of freshwater stocks or producer reserves.
6. Keep current surface-water-persistence assertions, finite-stock checks and full-state continuation comparison. Add generator-fallback cases and malformed depth/salt cases only where they verify the new contract. Normal regional resume and unchanged-world checks remain applicable.

No new hardcoded depth, salt concentration or source ledger policy is approved by this document. Those assumptions must be part of the reviewed topology contract. New water cannot quietly be a population rescue, and closing water cannot erase living tissue or dissolved salt.

Completion for A0 requires the existing changed-water test and relevant exact resume checks to pass while corrupt data still rejects. Current status is INCOMPLETE. Architecture review is still pending; this preflight does not authorize implementation.
