# Support-based body carriage

The renderer now derives a smooth support-load envelope from its existing planted-foot phase. Torso, hips and neck lean toward the weighted supporting limb directions and settle as support is shared. Sturdy-leg animation metadata produces a more deliberate transfer. This is presentation in artwork units, not physical forces, mass, balance simulation, navigation or a new biological capability.

`genvo.js` reads `support-load.js`; existing stride, lift, planted decisions and every candidate foot coordinate remain unchanged. Raised striking limbs cannot contribute support. Static/display/legacy and swimming/flight/climbing/specialized-action paths remain unchanged. The pure function consumes no RNG and stores no animal/save fields. Current pose-cache inputs still determine all output; no moving-sprite or terrain-cache optimization was removed.

`tests/support-load.mjs` passes 20,480 eight-direction poses with continuous bounded carriage, sturdy-build contrast and exact foot geometry. A further 1,568 **final authored socket insertions** verify that moving the torso does not drag feet after the actual draw-leg attachment correction. Existing gait, motion, prediction, turn, architecture and canonical source checks pass. Stride arithmetic is retained bit-for-bit, and older static/swim/display/legacy reference comparisons remain exact.
