# Indexed regional persistence

`src/persistence/regional-records.js` now supplies the physical storage boundary used by SaveManager for planetary checkpoints. It does not simulate ecology or replace World, Simulation, the snapshot codec or regional ownership. IndexedDB `genvo8-saves` upgrades from version 1 to 2 by adding the `regions` object store; existing saves and metadata are retained unchanged.

## Live storage path

Planetary saves now write a lightweight slot root and separate keyed records for the active region, each archived biological session and each surveyed physical World. The root contains coordinates, capture identity, metadata and record descriptors, without terrain, animal or controller payloads. Keys include world slot, record kind and absolute aligned region identity. Complete session envelopes retain actual clocks, replay/environmental ledgers, inheritance, controllers, resources and unique traveler ownership. No departed ecology is regenerated to replace missing records.

Root, region payloads and metadata commit in one readwrite transaction. Obsolete records from the previous index are deleted in that same transaction, including an old active-region record when it becomes an archived session. Failure after queued region writes aborts the entire commit. A first queued root read guards against a stale writer overwriting a newer committed capture. All payload puts still clone synchronously in the capture turn; the guard does not defer reading live simulation objects. Missing, stale, foreign-slot or duplicate indexed payloads fail closed.

SaveManager's `loadRegionSnapshot(region,{slot,kind})` reads one requested active/session/survey record without loading other regions or the active terrain from the index. Root and payload reads share one readonly transaction, preventing mixed captures during a concurrent write. `loadSnapshot` assembles the complete established snapshot shape for existing Continue, restore, fork and export consumers. Those consumers therefore still materialize all saved regions; this pass does not yet change their RAM residency. Local worlds retain their monolithic save path. Read-only movement backups remain untouched; their legacy complete snapshots continue to load. Clearing/deleting an indexed world removes all of its referenced records atomically.

The database connection closes on version change. A blocked upgrade reports the need to close other tabs and permits a later retry; it does not silently discard data or leave a permanently rejected cached connection.

## Next dependency and remaining limits

The existing live Atlas and offscreen scheduler still hold the complete current regional working set. Their 16 inactive archives/17 materialized Worlds limits, whole-Simulation crossings, finite projection, large restore work and atomic simulation stalls remain. Every current planetary save still rewrites its current records; dirty-only persistence and immutable payload reuse are not implemented. This is the integrated indexed-storage dependency, not a claim that the planet now streams or supports unlimited exploration.

Next connect selective storage reads to explicit residency/eviction and asynchronous neighbor preload, preserving actual regional ecology and global ownership. Distant ecological scheduling must remain bounded and physically coherent, rather than disappearing or being fabricated on load. Continuous renderer/camera/navigation seams and a versioned globe/projection policy remain required. The separate known historical missing-terrain topography failure remains unresolved and the broad B1/full suite is not reported green.
