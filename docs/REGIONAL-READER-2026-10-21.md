# Bounded persisted regional reads — October 21, 2026

`SaveManager.openRegionalReader(slot, {capacity})` opens the existing indexed checkpoint without loading its Worlds. The reader holds a detached lightweight manifest and admits at most `capacity` decoded leases, including pending requests (default two, supported range one to four). `acquire(kind, key)` reads only the indexed active/session/survey record. An exhausted reader refuses another admission until a lease is released; it never evicts an in-use biological owner. `release()` clears the reader's payload reference, is idempotent and does not delete persisted ecology. `close()` clears all leases and rejects pending admissions. Callers must also release their own retained aliases; this API cannot bound arbitrary references outside its ownership.

Each page read checks the original root capture inside the same readonly transaction that reads its payload. A replacement save or deletion invalidates future admissions, requiring a fresh reader. Already acquired pages still belong to their original capture. A caller must not combine them with a newer reader's pages or publish them as a new checkpoint without the canonical transaction/biological validation. Mutating a decoded page cannot mutate its persisted source. This is storage ownership, not a new World, simulation, catch-up authority or permission to discard modified organisms.

Compatibility full checkpoint loads now enqueue only one payload request at a time, chaining requests inside the same IndexedDB transaction. They retain their previous exact complete return value and snapshot isolation. They still collect all payloads for the existing synchronous restore. Legacy monolithic saves continue through the existing codec; leased readers explicitly require an indexed checkpoint rather than silently converting historical storage. No database version, save schema or ecological policy changed.
