# Independent staging and atomic regional publication — October 21, 2026

The existing reader can now `beginStage()` over its captured directory. `RegionalCheckpointStage.stage(kind, payload)` persists one existing owner's candidate under a unique unpublished capture key, then retains only its identity/clock/reference metadata. No currently indexed record is overwritten. Callers can release each decoded region after its stage completes. The stage requires an active transaction/allocation record, validates complete indexed ownership and ID watermarks, and rejects missing/foreign owners, nested archives, clock rewind and invalid reference formats. It does not decide physics or infer which owners a conservative transaction must include.

`publish()` atomically switches the root and metadata to the prepared references after checking the previous root under the write lock and confirming every staged key exists. Replaced old records are deleted in that same transaction; unrelated references stay owned. A failed publication preserves the old complete checkpoint and leaves candidates available for retry. `abort()` removes only that stage's unpublished keys. It is idempotent and cannot remove a successfully published generation. Concurrent operations on one stage reject.

New capture-key references use the explicit `indexed-regions/3` format and `capture-key/1` entry marker. Older fixed-key v1/v2 records can be retained by a v3 root. Existing ordinary changed-page saves can update v3 roots without losing retained immutable records, and complete saves compact back to their existing v2 fixed-key form atomically. Older saves remain readable; neither IndexedDB version nor biological snapshot schema changed. Active records must retain their regional owning collection even when it is represented by an empty payload list; absence cannot silently orphan archived worlds.

Stored `replayNext()` now uses this staging path. It reads the due remote region, runs the shared canonical kernel, stages the candidate and releases it before reading the active record. It stages the active allocation headers, releases that record and publishes the prepared root. A capacity-one reader therefore suffices; only one decoded persisted lease exists at a time. The temporary canonical Simulation/candidate still uses transient buffers for that region. The guarantee is bounded decoded region ownership, not a claim of a single array copy or measured total peak bytes. Failure or stale reads/publication close the reader and abort its unpublished candidates. Exact Continue/load semantics and the live resident scheduler remain unchanged.
