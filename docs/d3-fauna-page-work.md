# D3 canonical fauna lifecycle: once-tick page execution

D3 is the first page-attributed **live fauna lifecycle** slice. It modifies the actual phase responsible for real deaths, egg hatching and funded births. It does not create independent unloaded fauna populations or actor copies.

- `Simulation.animals` remains the single owner of every organism, genome, physical reserve and pregnancy. `World.pages` remains a read-only, evictable view. Animal AI, movement, predator engagement, mating and survival thresholds remain unchanged.
- The canonical `Simulation.update()` invokes `phaseLifecycle({once:true})`. The phase handles eggs exactly as before, then snapshots the actual actor array, visits each living actor **once in its original array order** through `visitLivingFaunaByPage`, removes dead actors in the same place and records completion. A child created during an actor callback joins the real canonical array but is not processed until the next lifecycle step, matching the previous snapshot iteration. Normal death/carcass and reproduction authorities remain unmodified.
- The scheduler attributes actual visited actors to the 64x64 page at the start of their callback, tallying count per page and a separate number for off-map actors. Finite out-of-map fixtures remain alive as normal but own no page. A duplicate living actor identity is an error, never a second receipt.
- The saved `pageFaunaWork` contains the last completed tick, count by page, outside count and total, but **no duplicate animal objects**. Repeated canonical lifecycle invocation during that tick is an exact no-op, so it cannot accidentally consume reserves or spawn another litter. Direct `phaseLifecycle()` calls stay ungated for controlled test fixtures, matching D1's scheduled versus explicit-phases distinction.
- A phase is recorded complete only after all actual actor callbacks and dead-actor filtering succeed. A pending/incomplete phase is fail-closed and will not be silently replayed over partly changed canonical bodies. This is **not** crash-safe rollback or a journal of each individual organism mutation. Interruption still requires a previously completed checkpoint.
- Saves retain schema 10 and validate receipt schema, page grid, nonnegative integer totals, pending state and future dates. Legacy saves without D3 metadata load without synthetic earlier history.
- Original random draws and per-actor order must remain identical to the pinned D2 baseline; CI compares full seeded snapshots after deleting only D3's new receipt.

`tests/page-fauna-work.mjs` covers real funded births, mortality, death removal from the page ledger, exact once behavior, actor order, out-of-map locations, duplicate identity, save/resume and invalid or legacy saves. All original crop/seed/page tests still run. The unchanged 500 ms 4x observer-play ceiling remains a separate required performance check; no exception or limit change is introduced.

D3 **does not** yet make region pages independently unloadable, perform remote AI without a global actor array, transfer material between independently owned worlds, simulate continents, or recover partially committed lifecycle steps. Its key deliverable is a tested deterministic single-execution boundary around the real lifecycle, alongside D1 real vegetation work and D2 real seed migration provenance.
